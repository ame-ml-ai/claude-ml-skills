# claude-ml-skills

Навыки (skills) Claude для работы с ML. Первый из них, `paper-to-code`, превращает статью в разбор, по которому можно учиться, и небольшую реализацию на PyTorch, в которой утверждения статьи проверяются тестами, а не только рисуются на графике.

## Примеры

Все три сгенерированы навыком, запущены и сверены со статьями. Разборы на английском и русском.

| Статья | Что показывает игрушечный запуск | |
|---|---|---|
| [**LoRA**](examples/lora) · [2106.09685](https://arxiv.org/abs/2106.09685) | На заложенном сдвиге ранга 4 LoRA r=4 восстанавливает настоящую поправку с ошибкой 3.6% и обходит полное дообучение (MSE 0.0007 против 0.0234, в 13 раз меньше параметров). На сдвиге полного ранга той же нормы проигрывает в 5.6 раза. Свой learning rate для каждого метода, 3 сида. | [разбор](examples/lora/breakdown.ru.md) · [код](examples/lora/main.py) |
| [**Transformer**](examples/transformer) · [1706.03762](https://arxiv.org/abs/1706.03762) | Учится разворачивать последовательности (999 из 1000 без ошибок) и выучивает правильную антидиагональ в cross-attention. Абляции: без позиционного кодирования точность падает до потолка «мешка токенов» (0.21), без warmup обучение разваливается, без 1/√d_k при d_k = 16 ничего не меняется. | [разбор](examples/transformer/breakdown.ru.md) · [код](examples/transformer/main.py) |
| [**DPO**](examples/dpo) · [2305.18290](https://arxiv.org/abs/2305.18290) | Совпадает с «reward model + точный RL» до 4 знаков и попадает на оптимальную границу; неявная награда коррелирует с настоящей на 0.976. Без веса σ log-вероятности проигравших ответов уходят в −∞. | [разбор](examples/dpo/breakdown.ru.md) · [код](examples/dpo/main.py) |

Каждый пример — один `main.py`, который работает на CPU ноутбука меньше минуты, ничего не скачивает и начинается с собственных тестов:

```bash
cd examples/dpo
pip install -r requirements.txt
python main.py           # тесты, эксперимент, assets/results.png
python main.py --test    # только тесты
```

В [`examples/TEST_REPORT.md`](examples/TEST_REPORT.md) — что проверялось и что пошло не так по ходу (начальный loss 46 вместо 2.4, абляция, которая ничего не изменила, статья, которая определяет одну величину двумя разными способами).

## Что делает навык

Дайте Claude ссылку на arXiv, ID или PDF. Он вернёт:

1. **Разбор:** TL;DR, проблема, основная идея, ключевые уравнения с размерностями тензоров и номерами разделов, привязанные к функциям в коде, пошаговый разбор, упрощения, подводные камни и три вопроса для самопроверки.
2. **Минимальную реализацию:** один `main.py` с тестами (размерности, переобучение одного батча, свойство самого метода) и демо, которое печатает реальные числа и сохраняет график.

Правила, которым он следует:

- Читать саму статью, включая приложения, и указывать прочитанную версию и то, что прочитать не удалось. Никогда не восстанавливать статью по памяти.
- Помечать как допущение каждое значение, которого нет в статье.
- Строить игрушку так, чтобы утверждение статьи могло и подтвердиться, и провалиться: заложенная структура или оптимум в замкнутой форме, с которым можно сравнить, и отрицательный контроль, где метод должен проиграть.
- Сравнивать честно: у каждого метода свой learning rate, выбранный по валидационной выборке; близкие результаты — на нескольких сидах.
- Проверять loss на шаге 0 (ln C для классификации, ln 2 для DPO).
- Запускать код и копировать вывод последнего запуска. Никогда не утверждать, что игрушечный запуск воспроизводит результаты статьи.

Отвечает на языке пользователя, код пишет на английском. Полные инструкции — в [`SKILL.md`](skills/paper-to-code/SKILL.md).

## Установка

**claude.ai**

1. Скачайте папку [`skills/paper-to-code`](skills/paper-to-code) и запакуйте её в zip.
2. Откройте **Settings → Capabilities → Skills**, нажмите **Upload skill** и выберите архив.

**Claude Code**

```bash
git clone https://github.com/ame-ml-ai/claude-ml-skills.git
cp -r claude-ml-skills/skills/paper-to-code ~/.claude/skills/
```

Перезапустите Claude Code. Навык подключится, когда вы пришлёте статью.

## Использование

```text
Вот статья: https://arxiv.org/abs/2305.18290
Объясни её и реализуй основную идею на PyTorch.
```

- `кратко` / `quick` — только TL;DR, основная идея и уравнения.
- `code only` — только реализация.
- «выложи в GitHub» — готовит репозиторий с README, графиком результатов и цитатой, предварительно уточнив название и видимость.

## Планы

- **pytorch-debugger** — пошаговый поиск ошибок размерностей, NaN и тихих багов обучения.
- **eval-builder** — проектирование и написание наборов оценок для ML-моделей.
- **kazakh-ml-glossary** — единые казахские переводы ML-терминов.

## Участие

Issues и pull requests приветствуются, особенно отчёты о реальных статьях, где навык ошибся. Чтобы добавить пример, повторите структуру [`examples/`](examples), приложите вывод последнего запуска и убедитесь, что `python main.py --test` проходит в CI.
